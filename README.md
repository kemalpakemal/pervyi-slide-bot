# Первый слайд

Telegram-бот студии дизайна карточек товаров для Wildberries, Ozon и Avito.

## Стартовый прайс

- Обложка — 790 ₽.
- Инфографика — 590 ₽ за слайд.
- 2 слайда — 1 290 ₽.
- 3 слайда — 1 890 ₽.
- 5 слайдов — 2 890 ₽.
- 7 слайдов — 3 790 ₽.
- 10 слайдов — 4 990 ₽.
- Дополнительный слайд — 490 ₽.

Цены хранятся в `config/price.yaml`.

## Генерация изображений через OpenAI GPT Image 2.6

Используется Image API с моделью `gpt-image-2.6-sunburst`. Для каждого слайда генерируется отдельная сцена-фон. Фото товара не отправляется в генератор фона и не перерисовывается: бот удаляет фон с исходного фото товара и накладывает исходный объект на сцену средствами Pillow.

Итоговый формат — 1200×1600. Клиенту отправляется только демо-копия:
- максимальная сторона 700 px;
- повторяющийся диагональный водяной знак «ПЕРВЫЙ СЛАЙД • ДЕМО»;
- крупная центральная надпись «ДЕМО».

Финальные PNG хранятся в закрытом Railway Volume `/data`. Чистые оригиналы этим workflow клиенту не отправляются.

### API-ключ

Нужен отдельный OpenAI API key. Подписка ChatGPT не включает API-баланс. Перед генерацией может потребоваться Organization Verification в Developer Console.

Добавь в Railway → `pervyi-slide-bot` → Variables:
- `OPENAI_API_KEY` — секретный API-ключ;
- `IMAGE_PROVIDER=openai`;
- `OPENAI_IMAGE_MODEL=gpt-image-2.6-sunburst`;
- `OPENAI_IMAGE_SIZE=1024x1536`;
- `OPENAI_IMAGE_QUALITY=medium`;
- `OPENAI_IMAGE_COMPLEXITY=medium`.

Не вставляй ключ в GitHub, код, Telegram или этот чат. Храни его только в Railway Variables.

Официальная тарификация GPT Image 2.6 зависит от количества image/text tokens, размера и качества. В официальном руководстве приведён пример $0.02469 за изображение при 823 выходных image tokens; фактическая сумма у каждого запроса отражается в API usage. Перед серийной генерацией проверь расходы в OpenAI Usage и установи лимит расходов для проекта.

### Команды генерации и согласования

1. Администратор принимает заявку.
2. Команда `/generate <ID>` создаёт слайды и водяные демо.
3. Бот отправляет демо администратору.
4. Администратор нажимает «Отправить демо клиенту» или «Перегенерировать».
5. Только после нажатия бот пересылает водяные демо заказчику.

Пример: `/generate 2c19e81f`.

### Требования к контенту

- Размеры, состав и технические характеристики можно показывать только при наличии подтверждения в брифе или на исходной упаковке/документе.
- Фон генератор создаёт без товара, текста, логотипов и числовых характеристик.
- Преимущества берутся из брифа клиента.
- Исходный товар компонуется поверх фона без генеративной перерисовки.

## Клиентский режим

- `/start` — главное меню.
- Пошаговый бриф: площадка, товар, преимущества, обязательные тексты, стиль, цвета, количество слайдов и срок.
- Приём фото и документов-изображений JPG/PNG/WEBP.
- Подтверждение брифа создаёт заявку в PostgreSQL и отправляет её администратору.
- «Примеры работ» — файлы из `content/examples/`.
- «Цены» — значения из `config/price.yaml`.
- «Связаться с автором» — передача сообщения администратору.

## Команды администратора

- `/orders` — последние 20 заказов и статусы.
- `/review <ID>` — повторно открыть заявку на проверку.
- В карточке заявки: принять, запросить уточнение, отклонить.
- `/generate <ID>` — генерация слайдов.
- `/health` — проверка БД.
- `/order` — создать черновик заказа из пересланных сообщений.
- `/paid` и `/remind` — заглушки; подтверждение оплаты и выдача чистых оригиналов пока не включены.

## Хранение

- PostgreSQL: клиенты, заявки, FSM, статусы и Telegram file_id.
- Railway Volume: исходные и сгенерированные изображения.
- `/stop` отключает инициативные сообщения.
- `/forget` удаляет профиль и связанные строки БД. Файлы на диске пока не удаляются автоматически.

## Railway

Переменные описаны в `.env.example`. Docker build выполняет `compileall` и останавливает деплой при синтаксических ошибках Python.
