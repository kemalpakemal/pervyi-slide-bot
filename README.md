# Первый слайд

Telegram-бот студии дизайна карточек товаров для Wildberries, Ozon и Avito.

## Стартовый прайс

- Обложка — 790 ₽.
- Инфографика — 590 ₽ за слайд.
- 2 слайда — 1 290 ₽.
- 3 слайда — 1 890 ₽.
- 5 слайдов — 2 890 ₽.
- 7 слайдов — 3 790 ₽.
- 10 слайдов — 4 990 ₽.
- Дополнительный слайд — 490 ₽.

Цены хранятся в `config/price.yaml`.

## Гибридная генерация изображений

### Режимы

- `IMAGE_MODE=auto`: при наличии `OPENAI_API_KEY` бот использует Images API. Если ключ отсутствует или генерация завершается ошибкой после повторов, заказ автоматически переходит в ручной режим.
- `IMAGE_MODE=manual`: API не вызывается, владелец получает пакет для ручной генерации.
- `OPENAI_BASE_URL`: базовый URL OpenAI или OpenAI-совместимого провайдера. Путь `/images/edits` добавляется автоматически.
- По умолчанию используется `gpt-image-2`, размер `1024x1536`, качество `medium`. Модель, размер и качество задаются переменными окружения.
- Для подключения стороннего API без доработки кода провайдер должен поддерживать тот же контракт: `POST /images/edits`, Bearer-аутентификацию, multipart-поля `image[]`, `model`, `prompt`, `n=2`, `size`, `quality` и ответ JSON `data[].b64_json`. Несовместимый API потребует отдельного адаптера; один только URL не делает разные API совместимыми.

### Запуск заказа

1. Клиент заполняет бриф и прикрепляет фото товара и референсы.
2. Администратор принимает заявку и нажимает **«Принять и создать»**.
3. В режиме auto бот отправляет исходное фото и референсы в Images API, запрашивает два варианта для каждого слайда, сохраняет оригиналы и формирует демо.
4. В ручном режиме (или после ошибки API) бот присылает владельцу один альбом с исходными изображениями и кратким промтом из брифа в подписи. Владелец отвечает готовыми изображениями на любое сообщение исходного альбома: по два варианта на каждый слайд. Бот сам определяет заказ и порядок вариантов.
5. Владелец получает альбом оригиналов без водяного знака и предпросмотр с водяным знаком.
6. Клиент получает только демо с водяным знаком и только после нажатия администратором **«Отправить демо клиенту»**.

Промт требует сохранить форму, пропорции, оттенок, фактуру, логотип, упаковку, этикетку и все видимые надписи товара. Референсы используются для композиции и стиля, а не как источник характеристик товара.

Перед отправкой в генератор проверяется реальное содержимое каждого файла, а не только расширение и MIME: допустимы JPEG, PNG и WEBP; проверяются размер файла, разрешение и целостность. EXIF-ориентация нормализуется. Ответ провайдера декодируется, проверяется как изображение и приводится к PNG до сохранения. Прозрачные PNG для демо компонуются на белый фон; водяной знак имеет контрастную обводку и центральную плашку «ДЕМО».

### Лимиты и безопасность

- `MAX_GENERATION_SLIDES` ограничивает число обрабатываемых слайдов.
- `MAX_ORDER_COST_USD` — потолок резервируемого бюджета заказа. `ESTIMATED_IMAGE_COST_USD` — резерв на одно выходное изображение; перед каждым платным вызовом проверяется резерв на две версии слайда.
- Резерв — локальная оценка, а не точная сумма счёта провайдера: стоимость входных фотографий и фактическое число токенов зависят от размеров и качества исходников. Для жёсткого финансового ограничения дополнительно установи лимит расходов в панели самого API-провайдера.
- Успешные API-вызовы и созданные изображения учитываются в `orders.brief.generation_metrics`. Неуспешные HTTP-ответы не увеличивают счётчик успешных вызовов.
- Повторяются только HTTP 502/503/504, сетевые ошибки и таймауты: максимум три попытки, экспоненциальная задержка, jitter и `Retry-After`. Все 4xx, включая авторизацию, баланс и rate limit, завершаются без повторов.
- Один и тот же idempotency key используется внутри повторов. Неоднозначный запрос не запускается заново после перезапуска; он уходит в ручную обработку.
- При старте незавершённые статусы `generating` и `sending_demo` восстанавливаются: генерация уходит в ручной режим, отправка демо возвращается на проверку.
- Только `ADMIN_ID` может запускать генерацию, загружать ручные варианты, согласовывать цену, подтверждать оплату и одобрять отправку клиенту.
- Водяной знак повторяется по всей площади демо и дополнен крупной надписью «ДЕМО».
- `TEXT_OVERLAY_ENABLED=true` включает дополнительную текстовую плашку, создаваемую Pillow-кодом. По умолчанию выключено.
- API-ключ и токен бота не выводятся в диагностические сообщения и логи.

Официальная документация:
- [Images API — редактирование изображений](https://developers.openai.com/api/reference/resources/images/methods/edit)
- [Image generation guide](https://developers.openai.com/api/docs/guides/image-generation)

## Клиентский режим

- `/start` — главное меню.
- Пошаговый бриф: площадка, товар, преимущества, обязательные тексты, стиль, цвета, количество слайдов и срок.
- Приём фото и документов-изображений JPG/PNG/WEBP.
- Подтверждение брифа создаёт заявку в PostgreSQL и отправляет её администратору.
- «Примеры работ» — файлы из `content/examples/`.
- «Цены» — значения из `config/price.yaml`.
- «Связаться с автором» — передача сообщения администратору.

## Команды администратора

- `/orders` — последние 20 заказов и статусы.
- `/review` — последняя заявка, ожидающая проверки; `/review <ID>` — открыть конкретную заявку.
- `/generate` или `/generate <ID>` — запустить генерацию для последней принятой заявки или выбранной заявки.
- На карточке заявки: принять, запросить уточнение, отклонить.
- Кнопки после генерации: «Повторить генерацию», «Продолжить вручную», «Отправить демо клиенту».
- `/health` — проверка БД.
- `/order` — создать черновик заказа из пересланных сообщений.
- `/quote ID СУММА [комментарий]` — сохранить согласованную цену и отправить её клиенту после отправки демо.
- `/paid ID СУММА [комментарий]` — вручную подтвердить полную оплату. Сумма должна совпасть с сохранённой ценой; после записи платежа бот выдаёт клиенту оригиналы без водяного знака как документы.
- `/deliver ID` — повторить незавершённую выдачу оригиналов. Бот хранит список уже отправленных вариантов и пропускает их при повторе.
- `/remind ID` — отправить напоминание; кнопка «📨 Напоминания» показывает активные заявки.


## Управление Hermes с телефона через существующего бота

Связка не создаёт второго Telegram-бота и не запускает второй процесс `getUpdates`. Существующий aiogram-бот остаётся единственным получателем обновлений Telegram.

1. В Railway задайте секретную переменную `HERMES_BRIDGE_TOKEN` (случайный секрет длиной не менее 32 байт).
2. Включите публичный HTTPS-домен сервиса Railway. HTTP-маршруты моста доступны только с правильным заголовком `Authorization: Bearer <token>`.
3. На телефоне запустите `hermes_phone_bridge.py` с переменными `HERMES_BRIDGE_URL` и `HERMES_BRIDGE_TOKEN`. Worker забирает задачи и выполняет их локальной командой `hermes -z`.
4. В существующем Telegram-боте администратор отправляет `/agent <задача>`. Ответ возвращается в тот же чат. `/agent_status` показывает последние задачи.

Мост выключен, пока `HERMES_BRIDGE_TOKEN` не задан. Команды доступны только одному владельцу — Telegram-пользователю с `ADMIN_ID`. Сотрудники и дополнительные администраторы не поддерживаются. Клиенты могут пользоваться только публичными функциями бота: оформление заказа, примеры, цены и связь со студией. Они не получают доступа к Hermes, внутренним заявкам, настройкам, рассылкам, платёжным операциям и инструментам разработки. Не публикуйте токен моста и храните его отдельно на Railway и телефоне.

## Хранение

- PostgreSQL: клиенты, заявки, FSM, статусы, метрики генерации и Telegram file_id.
- Railway Volume: исходные, оригинальные и демо-изображения.
- `/stop` отключает инициативные сообщения.
- `/forget` удаляет персональные поля, вложения и файлы на диске. Неоплаченные заявки удаляются; записи о зарегистрированных платежах остаются в обезличенном виде, без Telegram ID, username, имени и содержимого брифа.

## Конфигурация

См. `.env.example`. Чтобы включить автоматическую генерацию, добавьте ключ выбранного API-провайдера в `OPENAI_API_KEY`, установите `IMAGE_MODE=auto`, укажите совместимый `OPENAI_BASE_URL` и реальное имя модели. Секреты задаются только в переменных окружения Railway, не в Git. До подключения ключа заказ безопасно уходит в ручной режим. Внешний API и его биллинг в этом PR не включаются.

## Тесты

Тесты не обращаются к сети и не вызывают платные API. Они проверяют контракт запроса генератора, повторные попытки, корректность выходных изображений, EXIF, прозрачность и водяной знак:

```bash
pip install -r requirements.txt
python -m compileall -q .
BOT_TOKEN=123456:test-token ADMIN_ID=1 DATABASE_URL=sqlite+aiosqlite:///./ci-smoke.db STORAGE_PATH=./ci-smoke-data python -c "import bot"
python -m unittest discover -s tests -v
```
