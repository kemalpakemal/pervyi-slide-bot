# Первый слайд

Telegram-бот студии дизайна карточек товаров для Wildberries, Ozon и Avito.

## Текущий этап — MVP

### Клиентский режим
- `/start` — главное меню; `/cancel` или «Отмена» — выйти из любого шага; «Назад» — предыдущий шаг брифа.
- Пошаговый бриф: площадка, товар, преимущества, обязательные тексты, стиль, цвета, количество слайдов и срок.
- Приём фото, документов-изображений JPG/PNG/WEBP и ссылок/описаний референсов.
- Подтверждение брифа создаёт заявку в PostgreSQL и уведомляет администратора.
- «Примеры работ» — показывает файлы из `content/examples/`.
- «Цены» — читает только `config/price.yaml`. Пустые цены не выдумываются.
- «Связаться с автором» — передаёт сообщение администратору.

### Режим ассистента
1. Администратор пересылает боту сообщения клиента подряд.
2. Отвечает командой `/order` на одно из пересланных сообщений.
3. Бот собирает материалы этого отправителя за последние 30 минут и создаёт черновик заказа.
4. Бот не пишет клиенту автоматически. Если Telegram скрывает ID отправителя, заказ не создаётся автоматически.

### Команды администратора
- `/orders` — последние 20 заказов.
- `/health` — БД, запись в хранилище, настроенные опциональные провайдеры (без секретов).
- `/order` — создать заказ из пакета пересланных сообщений.
- `/paid` и `/remind` — пока заглушки; не подтверждают оплату и не отправляют напоминания.

### Хранение и ограничения
- Брифы, заказы, FSM-состояния и Telegram file_id хранятся в PostgreSQL.
- FSM переживает перезапуск приложения.
- Вложения пока хранятся как Telegram file_id; физическое копирование файлов в Railway Volume и проверка содержимого ещё не реализованы.
- `/stop` отключает инициативные сообщения (автоматических рассылок на этом этапе нет).
- `/forget` удаляет профиль и связанные записи из БД. Физические файлы пока не копируются в хранилище.

## Деплой на Railway (с телефона / из браузера)

Бот — это **worker** (long polling), веб-порт и домен не нужны. Push в `main` автоматически деплоит продакшен — тестируйте в ветках.

1. В проекте Railway добавьте сервис из GitHub-репозитория (сборка по `Dockerfile`, см. `railway.toml`).
2. Добавьте базу: **+ New → Database → PostgreSQL**.
3. Сервису бота добавьте **Volume** с точкой монтирования `/data`.
4. Во вкладке **Variables** сервиса бота задайте:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather (секрет, не публиковать) |
| `ADMIN_ID` | ваш числовой Telegram ID (узнать: @userinfobot) |
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` (форматы `postgres://` и `postgresql://` поддерживаются) |
| `STORAGE_PATH` | `/data` |
| `MAX_FILE_MB` | `15` |
| `MAX_FILES_PER_ORDER` | `12` |
| `PYTHONUNBUFFERED` | `1` |
| `LOG_LEVEL` | `INFO` (необязательно) |
| `ENABLE_LEAD_RADAR`, `IMAGE_PROVIDER`, `LLM_PROVIDER` | необязательно, на этапе 1 только показываются в `/health` |

5. Нажмите **Deploy**. Во вкладке **Logs** должны появиться строки: `Запуск бота`, `БД подключена`, `Бот авторизован: @имя_бота`, `Запускаю polling`.
6. В Telegram отправьте боту `/start`, затем (от имени админа) `/health` — проверка БД, записи в хранилище и опциональных провайдеров (секреты не выводятся).

Если в логах `Ошибка конфигурации` — проверьте `BOT_TOKEN` и `ADMIN_ID`. Ошибка Telegram `Conflict` означает, что одновременно запущен второй экземпляр бота (локально или вторая реплика) — оставьте ровно один.

Контейнер работает от root: Railway Volume монтируется с владельцем root, и непривилегированный пользователь не смог бы писать в `/data`.

Схема БД создаётся автоматически (`create_all`). Это создаёт недостающие таблицы, но **не изменяет** существующие — при изменении моделей понадобится миграция (Alembic).

## Локальный запуск и тесты

```
pip install -r requirements-dev.txt
cp .env.example .env   # заполните BOT_TOKEN и ADMIN_ID
python bot.py
pytest
```

## Что не входит в MVP

Генерация изображений, LLM, вырезание товара, шаблоны макетов, водяные знаки демо, ручное согласование, оплата, выдача оригиналов, лимит правок, сбор отзывов и lead radar. Эти функции будут добавляться отдельными этапами после проверки текущего.
